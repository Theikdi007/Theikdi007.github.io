Case study 07 · Maritime education · WebView

One login across native and web

OpenedDoor Exam gives seafarers access to exam schedules and online assessments, built for maritime training centers. The exams run on an existing web system, so the app wraps it in a WebView. The hard part was making the login feel like one app, not two.

Role
Senior Flutter Developer
Stack
Flutter · GetX · WebView
Platforms
iOS & Android

Get the app: App Store ↗ · Google Play ↗

01 / The setup

A native shell around a web exam system

Seafarers sign in, see their appointed exams and take assessments. The login screen is native Flutter; the exam itself runs in a WebView from the training center's web system.

02 / The problem

Two systems, one user who shouldn't log in twice

The exam lives on a web system with its own sessions, while the app has its own native login. Without a bridge, a seafarer would sign in to the app and then again inside the exam page, and could be thrown out mid-flow when one side's session ended.

03 / The fix

Pass the session in, and let the web talk back

I made the native app own the login and hand it to the web layer, with a way for the web page to report back.

01

Native login, token to the web

The user signs in natively and the session is passed into the WebView, so the exam opens already signed in.

02

JavaScript bridge

A JS channel lets the web page send events to Flutter, such as when the user should be sent back to the app.

03

Session kept on restart

The token is stored securely, so seafarers stay signed in between uses.

04

Clean handling of expiry

When the web session expires, the app returns the user to the native login instead of showing a broken page.

// Simplified: the web page can tell Flutter the session has ended.
controller
  ..addJavaScriptChannel('App', onMessageReceived: (msg) {
    if (msg.message == 'session_expired') authController.signOut();
  })
  ..loadRequest(examUri, headers: {'Authorization': 'Bearer $token'});
04 / The result

Feels like one app, ships like a web system

Seafarers sign in once and go straight to their exams, and the training center keeps running its existing web system. Wrapping it this way let the app reach the App Store and Google Play without rebuilding the exam engine.

1login for app and exam
2platforms from one Flutter shell
0exam logic rebuilt natively

What I took from it: a WebView app is only as good as its seams. Getting the login handover and the way back right is what makes a hybrid app feel native.
